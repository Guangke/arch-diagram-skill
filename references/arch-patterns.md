# 常见架构模式速查 / Architecture Pattern Reference

> 每个模式给出三件事：**组件清单**（画什么框）、**连接关系**（画什么线）、**布局要点**（怎么摆）。用户没指定风格时，按这里的结构 + `colors.md` 的语义色直接落图。

## 1. 分层微服务（经典三层）

- **组件**：客户端（Web/App）→ API 网关（鉴权/路由/限流，infra 灰）→ 业务服务 ×N（compute 蓝）→ 各服务专属数据库（data 绿）
- **连接**：客户端→网关→服务为实线同步调用；服务→数据库实线；跨服务调用可经网关或直连（直连画细线）
- **布局**：四条水平层带（客户端/接入/业务/数据），服务与库垂直对齐；数据库一对一归属，不共享

## 2. 事件驱动（EDA）

- **组件**：生产者服务、消息总线（Kafka/RabbitMQ，infra 灰）、消费者服务 ×N、事件存储（可选，data 绿）
- **连接**：生产者→总线虚线 `publish`；总线→消费者虚线 `consume`；总线→事件存储虚线 `append`；事件存储→消费者虚线 `replay`
- **布局**：总线居中，生产者居左、消费者居右，事件存储在总线正下方；全部异步虚线是本模式的视觉特征

## 3. CQRS（读写分离）

- **组件**：命令侧（Command API + 写处理器 + 写库）、查询侧（Query API + 读处理器 + 读库）、同步通道（事件总线/投影）
- **连接**：写路径实线，读路径实线，写库→（事件）→读库虚线标注"投影/同步"
- **布局**：左右两列分写读，同步通道横跨中间；读库标"反范式化视图"

## 4. Kubernetes 部署

- **组件**：外部负载均衡 → Ingress 控制器 → 命名空间（Namespace 框）内：Service + Pod ×N、ConfigMap/Secret（security 红）、控制平面（Master，infra）
- **连接**：流量路径实线；ConfigMap→Pod 点线（配置注入）
- **布局**：Namespace / 节点池用虚线组框表达；Pod 画成小矩形堆叠在 Service 之下

## 5. 服务网格（Service Mesh）

- **组件**：服务 A + Sidecar 代理（Envoy）、服务 B + Sidecar、控制平面（Istio，infra 灰）
- **连接**：App↔Sidecar 实线（本地回环）；Sidecar↔Sidecar 实线标 `mTLS`；控制平面→Sidecar 点线（策略下发）
- **布局**：两个"App + Sidecar"堆叠框左右对置，控制平面居中下方

## 6. 分层单体（Modular Monolith）

- **组件**：接入层 → 应用层（用例）→ 领域层（实体/领域服务）→ 基础设施层（DB/缓存客户端），模块用内部虚线框切分
- **连接**：自上而下单向实线；禁止画反向箭头（下层依赖上层）
- **布局**：严格水平层带，箭头只向下，是"健康单体"的判据

## 7. 数据管道（ETL / ELT）

- **组件**：数据源 ×N（external 橙）→ 采集 Ingest → 处理（清洗/转换）→ 存储（数仓/对象存储，data 绿）→ 服务层（API/看板）；旁路：可观测性（obs 紫）
- **连接**：主流水线左→右实线，线上标阶段动词（抽取/转换/加载）；各阶段→监控虚线旁路
- **布局**：单行主流水线 + 底部监控带；消费方从服务层向右下扇出

## 8. Lambda 架构（批流合一）

- **组件**：数据源、批处理层（高吞吐/延迟高）、流处理层（低延迟）、批视图、流视图、合并查询层
- **连接**：源→两层实线；批层→批视图、流层→流视图实线；两视图→查询层实线
- **布局**：源居顶，批/流左右两列，视图与查询层居底；两列用不同宽度区分（批宽流窄）

## 9. 缓存架构（Cache-Aside）

- **组件**：客户端、应用层、缓存（data 绿）、数据库（data 绿）
- **连接**：应用↔缓存：读 `GET`（hit 实线返回）/ miss 虚线去库；应用→数据库：`SELECT` + 回填 `SET` 虚线
- **布局**：缓存置于应用与数据库之间偏上；hit/miss 两条路径必须分开画，标签写清

## 10. VPC 网络（公私子网）

- **组件**：互联网 → Internet Gateway → 公有子网（ALB/NAT 网关，infra 灰）→ 私有子网（应用服务器）→ 私有子网（数据库主从，data 绿）；安全组（security 红）
- **连接**：入向流量实线；安全组→资源点线（规则挂载）；主从库间双向细线 `replication`
- **布局**：VPC 用一个大虚线组框，内部两个子框（公有/私有）；可用区用竖向虚线再切一刀

## 11. CDN 内容分发

- **组件**：用户 → 边缘节点（PoP）×N → 源站网关 → 源站（应用 + 静态存储）；DNS 调度（infra）
- **连接**：用户→边缘实线（就近接入）；边缘 miss→源站实线（回源），hit→用户虚线返回；DNS→用户点线（解析）
- **布局**：边缘节点横向一排居上，源站居底；回源线只从中间一个边缘节点画，避免蜘蛛网

## 12. 混合云 / 多区域

- **组件**：本地数据中心组框（本地应用/DB/缓存）、云上组框（云应用/DB）、专线或 VPN 通道（infra）；多区域变体：GSLB + 区域 A/B 两框
- **连接**：两框之间一条粗实线标注 `Direct Connect / VPN`；区域间数据库 `异步复制` 虚线
- **布局**：左右两个大组框对置，通道横跨中间；主区域组件画满，从区域可简化示意

## 13. 认证授权（OAuth 2.0 / OIDC）

- **组件**：用户（含浏览器）、客户端应用、授权服务器（security 红）、资源服务器（API）
- **连接**：授权码四步流程按序号标注（1 请求授权 → 2 登录同意 → 3 换 token → 4 带 token 访问）；token 相关线用红色系强调
- **布局**：按序列图布局（本模式推荐画时序而非拓扑）；步骤编号必须连续可见

---

## 选型提示

- 用户说"画架构图"没给更多信息 → 默认模式 1（分层）或按用户提到的组件映射最接近的模式
- 涉及"事件 / 消息 / 异步" → 模式 2；"读写分离 / 报表慢" → 3；"上云 / K8s" → 4；"加缓存" → 9
- 一个真实系统常是多个模式叠加：先画主链路所属模式，再用组框嵌套次要模式，不要一次全塞进去
